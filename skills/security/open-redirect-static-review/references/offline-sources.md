# Open redirect sources (offline notes)

This file carries attributed source information for ordinary offline review; the entries are paraphrases, not full copies. Read them first. When online, consult a suitable primary source only if a material protocol, version, parser, or policy detail is absent here and in the reviewed repository. This is optional. Version ranges not established locally remain unknown unless verified; never infer them from a title or search snippet, and never send private project code externally.

Research snapshot: **2026-11-03**.

## Protocol, browser, and security guidance

| Source | Local summary and review use |
|---|---|
| [RFC 9700, OAuth 2.0 Security Best Current Practice](https://datatracker.ietf.org/doc/html/rfc9700) | Sections 2.1 and 4.11 call for exact string comparison of registered redirect URIs, with the stated loopback-port exception for native apps, and warn against query-parameter-driven open redirectors. Trace validation on every branch that emits a redirect, including errors and consent denial. Host suffix checks and wildcard matching are not substitutes for exact registration matching. |
| [RFC 9110 §10.2.2, `Location`](https://datatracker.ietf.org/doc/html/rfc9110#section-10.2.2) | A `Location` value identifies the target of a 3xx response; a relative URI reference is resolved against the request URI. Review the emitted value and the browser's interpretation, not just the server helper's input. |
| [WHATWG URL Standard](https://url.spec.whatwg.org/) | Browser URL parsing includes normalization that may differ from a server-side URL parser. Track whitespace/control trimming, slash and backslash handling, dot segments, percent decoding, and authority parsing through the final navigation. A server parser accepting a value does not establish that a browser stays on the intended origin. |
| [CWE-601](https://cwe.mitre.org/data/definitions/601.html) | Describes a user-controllable destination causing a redirect to an untrusted site. Phishing is a common consequence; token or account compromise needs a separately demonstrated chain. CWE classification does not establish that a current code path is exploitable. |
| [OWASP Unvalidated Redirects and Forwards Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Unvalidated_Redirects_and_Forwards_Cheat_Sheet.html) | Prefer a fixed allowlist of server-owned destinations or route identifiers. If arbitrary internal paths are required, parse and constrain them against a fixed origin and use the same validated representation at the sink. Do not trust an input merely because its scheme/host was removed. |
| [CSP Level 3](https://www.w3.org/TR/CSP3/) and [MDN `default-src`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/default-src) | CSP is defense in depth, not a general restriction on top-level HTTP(S) redirects. `default-src` is a fallback for fetch directives; `form-action` constrains form submissions and `frame-ancestors` controls embedding. A script policy may limit some script execution but does not repair a redirect to an attacker-controlled web origin. Check the effective enforced policy; `Report-Only` does not block. |

## Framework and browser navigation references

| Source | Local summary and review use |
|---|---|
| [Symfony HttpFoundation](https://symfony.com/doc/current/components/http_foundation.html) | `RedirectResponse` emits a redirect response; treat it as a sink, not a sanitizer. Trace the URL argument and any caller-side validation. |
| [PHP `header()`](https://www.php.net/manual/en/function.header.php) | Sending a `Location` header directs the user agent to the supplied value and sets a 302 response unless a 201 or 3xx status was already set. The status affects redirect semantics, but neither it nor header emission validates the destination. Trace the final value, status, and all caller-side policy. |
| [Vue Router navigation](https://router.vuejs.org/guide/essentials/navigation) | `router.push()` and `router.replace()` perform programmatic route navigation and return a promise; `<RouterLink>` uses the same route-location shape. The docs recommend encoding each dynamic path segment or using named routes with parameters, but URL encoding is not destination authorization. These docs do not establish a security guarantee for arbitrary external-looking strings: check the installed major version, mode/base and exact implementation before classifying an external navigation. |
| [MDN `Location.assign()`](https://developer.mozilla.org/en-US/docs/Web/API/Location/assign) and [`Window.location`](https://developer.mozilla.org/en-US/docs/Web/API/Window/location) | Assigning or calling `assign()` on the browser location navigates to the supplied URL. These are client-side sinks; trace the value and effective URL parsing. A plain anchor that requires a user click is a different case. |
| [`skills` CLI documentation](https://github.com/vercel-labs/skills) | The CLI can install a selected skill from a local repository path as well as a remote repository. The installed folder contains the skill's references. The remote command requires repository/network access; for an offline host, stage the repository or package first and use a locally available CLI or copy the skill directory into the agent's configured location. |

## Published report summaries

| Source | Local case summary and limits |
|---|---|
| [Symfony HttpFoundation CVE-2024-50345](https://symfony.com/cve-2024-50345) | A URL validator using Symfony `Request` could interpret special characters differently from a browser and permit a redirect to another domain. The corpus records affected ranges `<5.4.46`, `6.0–6.4.13`, and `7.0–7.1.6`; the fix rejects invalid characters according to WHATWG URL rules. Confirm the installed version, validator, and redirect sink. |
| [Snipe-IT GHSA-mghp-5cq4-v6mg](https://github.com/grokability/snipe-it/security/advisories/GHSA-mghp-5cq4-v6mg) | Before 8.4.1, an HTTP `Referer` could be stored in session and later used as a redirect destination after a user action. The report names phishing. This is a delayed flow: inspect session writes and later reads, not only same-request taint. |
| [Sylius GHSA-9ffx-f77r-756w](https://github.com/Sylius/Sylius/security/advisories/GHSA-9ffx-f77r-756w) | Currency and locale switching, plus admin impersonation, used the request `Referer` directly. Public switching routes and the authenticated impersonation route have different reachability. The maintainer fix uses a named internal route. |
| [CakePHP Authentication GHSA-hhpq-7wg4-36jm](https://github.com/cakephp/authentication/security/advisories/GHSA-hhpq-7wg4-36jm) | Backslash handling in a login redirect helper could leave an attacker-controlled hostname after validation. The corpus records fixed releases 2.11.1, 3.3.6, and 4.1.1. Trace validation and any later URL normalization. |
| [Symfony Routing CVE-2026-45065](https://symfony.com/cve-2026-45065) | In affected releases, a long alternation in a route requirement could be anchored incorrectly, allowing a matching substring and generation of a protocol-relative off-site path through Twig `path()`/`url()`. The corpus records fixes 5.4.52, 6.4.40, 7.4.12, and 8.0.12. URL generation alone is not automatic navigation; prove a redirect or browser sink. |
| [Vue Router issue #3946](https://github.com/vuejs/vue-router/issues/3946) | An issue report describes off-site navigation from untrusted values in `router.push()`, `router.replace()`, or route links with Vue 2.7.16 / Vue Router 3.6.5, HTML5 history mode, and an unset/empty/root base. It was an unreviewed issue lead when consulted, not a maintainer advisory or a universal rule. Confirm the exact implementation and configuration. |
| [Angular GHSA-w739-gvwx-grc3](https://github.com/angular/angular/security/advisories/GHSA-w739-gvwx-grc3) | The report is limited to SSR: a raw leading-`//` check ran before URL normalization, so a dot-segment form could become a protocol-relative path in a `Location` response. Do not generalize it to client-only SPA operation. |
| [React Router GHSA-2j2x-hqr9-3h42](https://github.com/remix-run/react-router/security/advisories/GHSA-2j2x-hqr9-3h42) | Certain values passed to `redirect()` could be interpreted as protocol-relative external destinations when application validation was insufficient. Declarative Mode (`<BrowserRouter>`) is excluded by the advisory; check the current package version and framework/data mode. |
| [Next.js GHSA-p9j2-gv94-2wf4](https://github.com/advisories/GHSA-p9j2-gv94-2wf4) | Configuration-level `redirects()` could interpolate a request-controlled hostname and send a browser to an arbitrary host. The related `rewrites()` behavior is a server-side request/SSRF concern, not a browser open redirect; classify it separately. |
| [Feathers GHSA-ppf9-4ffw-hh4p](https://github.com/feathersjs/feathers/security/advisories/GHSA-ppf9-4ffw-hh4p) | An unvalidated redirect query value was appended to a base origin and persisted through an OAuth callback. The advisory reports authorization-code/access-token leakage and account takeover; such impact requires the complete callback and exchange chain. A string prefix check does not prove authority confinement. |
| [n8n GHSA-f6x8-65q6-j9m9](https://github.com/advisories/GHSA-f6x8-65q6-j9m9) | An unauthenticated OAuth client-registration endpoint accepted arbitrary redirect URIs; the consent-denial branch later redirected to the URI without validation. Preconditions include registration and a victim interacting with the consent flow. Inspect denial/error branches as well as successful callbacks. |
| [Redash GHSA-rfgc-hc86-pxrv](https://github.com/getredash/redash/security/advisories/GHSA-rfgc-hc86-pxrv) | `get_next_path()` removed scheme and network location but left repeated leading slashes; Flask `redirect()` and browsers treated the result as protocol-relative. The case illustrates why stripping scheme/host is not a complete destination policy. |
| [Authlib GHSA-w8p2-r796-3vmq](https://github.com/advisories/GHSA-w8p2-r796-3vmq) | An unsupported-`response_type` branch used a supplied redirect URI before client lookup and normal URI validation. The advisory reports an unauthenticated redirect without valid client registration. Inspect early error paths before ordinary validation. |

The table is a compact research index, not a substitute for the current implementation's own source evidence. A similar advisory does not establish a finding in the reviewed project.
