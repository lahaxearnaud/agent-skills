| [CWE-59](https://cwe.mitre.org/data/definitions/59.html) | Covers improper link resolution before file access. A lexical path check can pass while a symlink resolves outside the intended root. Verify whether the sink follows links and whether an attacker can create or replace them. |
| [CWE-180](https://cwe.mitre.org/data/definitions/180.html) and [CWE-174](https://cwe.mitre.org/data/definitions/174.html) | CWE-180 addresses validating before canonicalization; CWE-174 addresses double decoding. Trace the exact representation checked and the representation later interpreted by the framework, library, or filesystem. These categories do not prove a particular transformation occurs. |
| [RFC 3986, URI normalization](https://www.rfc-editor.org/rfc/rfc3986) | Percent-encoding and URI dot-segment removal are URI-layer rules. They do not define operating-system filesystem canonicalization, symlink resolution, or how every framework decodes a request. Trace each parser boundary separately. |
| [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) | Prefer server-generated storage names, storage outside executable/public roots where appropriate, layered validation, and safe archive handling. Filename validation alone is not path confinement; archive entries and the final filesystem destination still need a safe policy. |

## API behavior notes

| Source | Local summary and limits |
|---|---|
| [Symfony Filesystem Path component, current docs](https://symfony.com/doc/current/components/filesystem.html) and [Symfony 5.x docs](https://symfony.com/doc/5.x/components/filesystem.html) | The 5.x documentation says `Path` was introduced in Symfony 5.4 and documents the same canonicalization rules as the current page: remove `.` segments, resolve `..` where possible, convert backslashes to `/`, normalize root/trailing separators, preserve schemes such as `phar://`, expand `~`, retain leading `..` in relative paths, and return malformed paths unchanged. `isBasePath()` compares canonicalized path relationships (the docs show both a parent-resolving true case and an escaping false case); it does not inspect filesystem objects. These helpers do not resolve symlinks or close a check/use race. For Symfony versions before 5.4 or behavior outside the documented cases, inspect the exact source or mark it unknown. |
| [PHP `realpath()`](https://www.php.net/manual/en/function.realpath.php) | Resolves `.`/`..` and symbolic links for an existing accessible path and returns `false` when resolution fails, including for some missing or inaccessible paths. A check followed by a later open/write can race; a non-existing destination needs a safe parent/create strategy. |
| [PHP `ZipArchive::extractTo()`](https://www.php.net/manual/en/ziparchive.extractto.php) | The method extracts all or selected archive entries into a destination and returns success/failure; the manual documents permission behavior but does not provide a general security guarantee for every PHP/zip version, platform, member type, or caller-managed flow. PHP ships or may use a separately packaged `zip` extension, so record both the PHP build and extension package where they differ. Historical PHP reports below document platform- and version-specific escapes. Inspect the exact runtime, archive names, destination argument, links, and write boundary; do not infer confinement from the API name or current manual alone. |
| [Node.js `path` API](https://nodejs.org/api/path.html) | `resolve`, `join`, `normalize`, and `relative` are lexical operations with platform-specific separators and absolute-path behavior. They do not resolve symlinks. `relative(root, target)` can support component-aware checks, but the result and final filesystem object still need to be examined at the sink. |
| [Java `SecureDirectoryStream`](https://docs.oracle.com/en/java/javase/27/docs/api/java.base/java/nio/file/SecureDirectoryStream.html) | Provides directory-relative operations intended to reduce races while accessing entries beneath an open directory. Provider support is optional; do not assume it is available or used without source and runtime-provider evidence. |
| [Python `zipfile`](https://docs.python.org/3/library/zipfile.html) | Standard extraction helpers apply documented path cleanup, but that does not automatically protect caller-managed paths, custom extraction code, link handling, every version, or later writes. Inspect the exact API call and the application wrapper. |

## PHP ZIP behavior and reported fixes

| Source | Local summary and limits |
|---|---|
| [PHP bug #70350 / CVE-2014-9767](https://bugs.php.net/bug.php?id=70350), [PHP 5 changelog](https://www.php.net/ChangeLog-5.php), [PHP 7 changelog](https://www.php.net/ChangeLog-7.php), and [PECL `zip` 1.13.0](https://pecl.php.net/package/zip/1.13.0) | The report describes archive directory entries whose unsanitized name was used while creating a directory, allowing `../` to create a directory outside the extraction root; the report distinguishes this from writing file contents. PHP changelogs record the fix in 5.4.45, 5.5.29, 5.6.13, and the PHP 7.0.0 changelog; PECL `zip` 1.13.0 also lists the fix. Older vendor/backported builds need their own evidence. The source notes possible inode exhaustion or web-visible directory spam as conditional consequences. |
| [PHP bug #81420 / CVE-2021-21706](https://bugs.php.net/bug.php?id=81420), [CVE record](https://www.cve.org/CVERecord?id=CVE-2021-21706), [PHP 7 changelog](https://www.php.net/ChangeLog-7.php), [PHP 8 changelog](https://www.php.net/ChangeLog-8.php), and [PECL `zip` 1.19.5 for Windows](https://pecl.php.net/package/zip/1.19.5/windows) | The reported escape is Windows-specific: an archive member beginning with `/` can be treated as rooted on the current volume and escape the supplied extraction directory. The CVE record lists affected upstream lines as 7.3.x before 7.3.31, 7.4.x before 7.4.24, and 8.0.x before 8.0.11, on Microsoft Windows; PHP changelogs confirm the fix in those releases. The PECL `zip` 1.19.5 Windows package also lists the #81420 fix. PHP recorded fix commit `df2ceac` on 2021-09-21. Check the actual PHP/zip build and vendor backports; do not apply these upstream ranges to other branches or packages without evidence. |
| [PHP bug #73910](https://bugs.php.net/bug.php?id=73910) | A report against PHP 5.6.29 / 7.1.0 describes a NUL byte in the `extractTo()` destination argument affecting path handling; a patch was committed in January 2017. The record was closed as a bug, not assigned a CVE, and does not establish a complete release range or universal exploitability. Treat it as a version-specific review lead, not proof that current `extractTo()` is vulnerable. |
