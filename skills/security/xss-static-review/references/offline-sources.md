# XSS sources (offline notes)

This bundle paraphrases the technical guidance and published-report details cited by the skill. It is not a mirror of the upstream pages. Keep original URLs for attribution and later updates; do not fetch them during an offline source review. Exact affected releases not stated below remain governed by the linked advisory and should be marked unknown unless the local dependency evidence resolves them.

Research snapshot: **2026-11-03**.

## Framework and prevention guidance

| Source | Local summary and review use |
|---|---|
| [Twig `escape` filter](https://twig.symfony.com/doc/3.x/filters/escape.html) | Twig's `escape` filter encodes for a selected strategy; HTML escaping is not interchangeable with JavaScript, CSS, or URL validation. Autoescaping and the strategy depend on template configuration. `raw`, `Markup`, and custom filters marked safe can suppress later escaping; inspect the final output context and transformations. |
| [Vue security guide](https://vuejs.org/guide/best-practices/security) | Vue escapes ordinary interpolated text, but `v-html` renders HTML and must not receive untrusted HTML without a suitable sanitizer. Do not compile attacker-controlled templates. Validate URLs and inspect the final destination; escaping text does not make a URL trustworthy. Server-side validation remains necessary for data consumed by multiple clients. |
| [Symfony HtmlSanitizer](https://symfony.com/doc/current/html_sanitizer.html) | The component sanitizes user-provided HTML according to configured allowed elements, attributes, and URL rules. Select the API and policy for the destination; inspect installed version and configuration. A sanitizer does not secure later concatenation or a different output context. |
| [OWASP XSS Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html) | Use context-appropriate output encoding for text and attributes, safe DOM sinks where possible, and HTML sanitization only when rich HTML is a feature. URL validation and script/HTML encoding solve different problems. Treat CSP as defense in depth, not as a substitute for fixing the injection path. |
| [MDN Content Security Policy guide](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) | CSP can restrict script loading/execution through directives such as nonces, hashes, and `script-src`; it is defense in depth. Check the effective enforced policy, not just source configuration. `Report-Only` reports rather than blocks; a nonce-authorized script can still mishandle attacker-controlled data. |
| [OpenCode skills documentation](https://opencode.ai/docs/skills) | Skill discovery and local package paths are client-tool behavior, not part of XSS analysis. This repository's skill directory includes its required references; transfer the complete package before using it offline. Verify the location recognized by the installed OpenCode version. |

## Published report summaries

| Source | Local case summary and evidence limit |
|---|---|
| [AVideo GHSA-wfq5-qgqp-hvhv](https://github.com/WWBN/AVideo/security/advisories/GHSA-wfq5-qgqp-hvhv) | An attacker-controlled URL passed through JSON serialization and later reached browser `innerHTML`. JSON serialization did not make a later HTML sink safe. The exact route and affected release must be read from the local application and its dependency evidence. |
| [Sylius GHSA-mx4q-xxc9-pf5q](https://github.com/Sylius/Sylius/security/advisories/GHSA-mx4q-xxc9-pf5q) | Authenticated stored XSS arose where entity names were rendered as raw HTML in multiple shop/admin locations. Review every rendering of the same value, not only its first template. |
| [Symfony WebProfiler GHSA-hmr5-2xcr-v8pp](https://github.com/symfony/symfony/security/advisories/GHSA-hmr5-2xcr-v8pp) | The profiler's file excerpt rendering could display non-PHP file content without escaping. Exposure depends on access to the development/debug profiler and vulnerable component versions; do not treat debug pages as safe merely because they are not intended for production. |
| [Twig GHSA-jv8m-2544-3pg3 / CVE-2026-46637](https://github.com/twigphp/Twig/security/advisories/GHSA-jv8m-2544-3pg3) | In `twig/markdown-extra` and `twig/cssinliner-extra` before 3.26.0, `html_to_markdown`, `markdown_to_html`, and `inline_css` were declared `is_safe => ['all']`. The Markdown converter can decode HTML entities inside code spans/blocks, turning encoded markup into literal HTML that becomes active if later rendered in an HTML page; the other two filters emit HTML, which is not safe for JavaScript, CSS, or URL contexts. Fixed in 3.26.0: the plain-text converter no longer claims a safe context, while HTML-producing filters claim only `html`. Verify the filter/package version, input control, declaration, and final context; an HTML fragment is not safe in every context. |
| [Symfony HtmlSanitizer GHSA-hhg7-c65m-h7ff](https://github.com/symfony/symfony/security/advisories/GHSA-hhg7-c65m-h7ff) | The URL-attribute sanitizer omitted attributes including `action`, `formaction`, `poster`, and `cite`, allowing a `javascript:` URI to survive sanitization in affected releases. The corpus records affected ranges `>=6.1,<6.4.40`, `>=7,<7.4.12`, and `>=8,<8.0.12`. Check both sanitizer configuration and which URL-bearing attributes reach the browser. |
| [Symfony UX Icons GHSA-6v8j-33hc-mv84](https://github.com/advisories/GHSA-6v8j-33hc-mv84) | Unsanitized SVG from local files or on-demand Iconify responses could be rendered as trusted HTML. Inline SVG can contain script elements and event-handler attributes. The condition is control or compromise of one of those icon sources plus rendering through the affected path; verify version and actual source. |
| [Adminer GHSA-h6jr-7pr6-grgj](https://github.com/vrana/adminer/security/advisories/GHSA-h6jr-7pr6-grgj) | A remote MySQL server version string could reach a script through a regex failure branch. The script already had a valid CSP nonce, so the nonce authorized the containing script rather than making its data safe. A victim must connect to a controlled server or the advisory's alternate chain must apply. |
| [Chamilo GHSA-ppw9-gf4r-5c39](https://github.com/chamilo/chamilo-lms/security/advisories/GHSA-ppw9-gf4r-5c39) | Stored social-wall content supplied through an API reached Vue `v-html` without the stated DOMPurify protection; the advisory title records versions below 2.0.3. Trace the writer role, API transformation, and viewers. |
| [Grafana GHSA-7rqg-hjwc-6mjf](https://github.com/advisories/GHSA-7rqg-hjwc-6mjf) | A Text-panel rendering cycle temporarily exposed unfiltered HTML before a later cycle sanitized it. The report requires multiple interactions and an Editor who changes the panel plus a victim who edits it and selects Markdown/HTML. Review previews and intermediate states, not only final saved output. |
| [Open WebUI GHSA-v2qm-5wxj-qhj7](https://github.com/advisories/GHSA-v2qm-5wxj-qhj7) | SVG model profile data was served inline on the application origin. The report distinguishes direct document navigation from ordinary `<img>` loading; a user able to create or modify a model and a victim opening the URL are relevant conditions. Check sibling endpoints after a fix. |
| [FreeScout GHSA-cvr8-cw5c-5pfw](https://github.com/freescout-help-desk/freescout/security/advisories/GHSA-cvr8-cw5c-5pfw) | An SVG sanitizer failure was followed by partial regex removal, and the resulting file could be served inline. Review error fallbacks, MIME type, extension/byte validation, and the browser's document context; a weaker fallback must not accept data after a strict sanitizer fails. |
| [Mermaid GHSA-7rqq-prvp-x9jh](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-7rqq-prvp-x9jh) | With the affected version and KaTeX support, a sequence-diagram label reached `innerHTML` during dimension measurement before/alongside final rendering. The advisory records affected versions `>=11.0.0-alpha.1,<11.10.0` and `>=10.9.0-rc.1,<10.9.4`. Search measurement and preview sinks, not only the final diagram. |
| [AVideo GHSA-2fhx-q92v-5fhv](https://github.com/advisories/GHSA-2fhx-q92v-5fhv) | A WebSocket message fix removed a field in one JSON branch while another prioritized key retained it, leaving a stored-XSS path. The report's version metadata did not list a fixed release in the corpus snapshot; confirm current advisory status and trace all schema variants. |
| [Rails GHSA-89vf-4333-qx8v](https://github.com/rails/rails/security/advisories/GHSA-89vf-4333-qx8v) | Mutating a `SafeBuffer` and then formatting it could preserve an incorrect safety state, bypassing expected autoescaping. Review trust/safety metadata after in-place transformations; do not assume every use of `SafeBuffer` is vulnerable. |
| [Froxlor GHSA-43gm-9rr3-cx7g](https://github.com/advisories/GHSA-43gm-9rr3-cx7g) | DNS TXT data passed through a non-escaping `wordwrap` callback and a Twig `raw` output into an admin table. The reported conditions include DNS/editor features, a permitted editor, an administrator viewing the zone, and a CSP allowing inline script. Format validation is not HTML encoding. |
| [Nextcloud Deck GHSA-mg7w-x9fm-9wwc](https://github.com/nextcloud/security-advisories/security/advisories/GHSA-mg7w-x9fm-9wwc) | The publisher labels the HTML-comment case self-XSS. The local report summary does not establish cross-account delivery, so do not claim an inter-user attack unless the reviewed flow proves another account can receive and render the value. |

## Evidence limits

These reports demonstrate patterns in their own products and versions. They do not prove an audited project is vulnerable. The original URLs are provenance, not required evidence to repeat during offline review; if a local summary lacks a detail, state it as unknown instead of reconstructing it from the advisory title.
