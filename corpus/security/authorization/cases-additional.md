## Public product advisories

1. **Spree — authenticated order/address IDOR (CVE-2026-22588).** Source facts: an authenticated user could edit an order they own with another user’s address identifier; the backend linked and returned that address. [CVE record](https://www.cve.org/CVERecord?id=CVE-2026-22588). **Review rule:** scope nested address lookup to the current principal and order before mutation/serialization. **Unknown:** whether any deployment was exploited.

## Proposed review rule

For every route, resolver, background action, and nested-resource lookup that accepts an object identifier, trace the loaded object to its canonical owner/tenant and verify the caller has permission for the requested action. Test reads, writes, deletes, exports, status/search/retrieval paths, and child objects independently. Do not treat authentication, UUID unpredictability, a parallel URL parameter, or authorization on a sibling endpoint as object authorization. This is a synthesis proposed for code review; it is not a direct quotation from any one case.
