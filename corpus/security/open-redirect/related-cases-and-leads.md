# Related cases and lower-confidence leads

These examples are useful for review coverage, but **do not count toward the 60 published advisory/CVE cases**. Their evidence category differs, or the primary behavior is a neighboring navigation/XSS primitive rather than an HTTP/browser open redirect.

## Unreviewed issue report

### Vue Router 3: browser-side external navigation through backslash normalization

The open GitHub issue reports that untrusted data passed to `router.push()`, `router.replace()`, or `<router-link>` can navigate off-site when Vue 2.7.16/Vue Router 3.6.5 use HTML5 history mode and an unset, empty, or `/` base. The author attributes this to browsers normalizing backslashes and scheme-relative URLs; the report also calls it a bypass of earlier slash-cleanup fixes. The issue was still open when consulted on 2026-11-03, with no maintainer security advisory or confirmed project fix found. Treat it as a **lead from an issue reporter**, not a verified project vulnerability or a rule that applies to all Vue Router versions. [Vue Router issue #3946](https://github.com/vuejs/vue-router/issues/3946)

## CVE records with limited technical detail

### Cradle eCommerce: `returnUrl` on the login form (CVE-2026-3318)

NVD identifies an open redirect in the latest demo version of Cradle eCommerce but explicitly notes that the record is not being prioritized for NVD enrichment. A secondary source attributes it to an unvalidated `returnUrl` on the login form; that parameter detail is not in the short NVD description. Keep the CVE as a lower-detail lead until the vendor/demo source and code path can be verified. [NVD record](https://nvd.nist.gov/vuln/detail/CVE-2026-3318)

### ViewerJS 0.5.8: URL tags in opened content (CVE-2024-25676)

The CVE record and an independent security advisory describe URL tags in ViewerJS content leading to external navigation and out-of-band resource loads. The available public record does not provide a maintainer advisory or enough source detail to establish a general redirect helper pattern. Treat it as a **third-party documented case** that motivates reviewing document viewers and URL-bearing formats, not as a reproduced exploit. [CVE record references](https://www.cve.org/CVERecord?id=CVE-2024-25676), [Excellium advisory](https://excellium-services.com/cert-xlm-advisory/cve-2024-25676)

## Adjacent navigation and XSS cases (not open-redirect findings)

### Nuxt: reflected XSS in `navigateTo(url, { external: true })` (CVE-2026-45669)

This is an XSS bug in the HTML meta-refresh response generated by an external redirect. The destination was incompletely escaped in the `content` attribute, allowing attacker-controlled HTML/JavaScript to execute under the application origin before navigation. It demonstrates a **redirect-response-to-XSS chain**, but the finding class is reflected XSS, not merely open redirect. [Nuxt advisory](https://github.com/nuxt/nuxt/security/advisories/GHSA-fx6j-w5w5-h468)

### `html_sanitize_ex`: sanitizer permits meta-refresh navigation (CVE-2026-66829)

The advisory says the sanitizer allowed a `<meta http-equiv="refresh">` element that could navigate the document to an attacker-controlled destination. This is HTML-driven navigation from sanitized content, not a server `Location` redirect. Keep it as a neighboring document-navigation primitive and inspect the surrounding rendering and sanitizer configuration. [Maintainer advisory](https://github.com/rrrene/html_sanitize_ex/security/advisories/GHSA-2c6f-3j54-xpcr)

### Nuxt `navigateTo({ open })`: script-scheme execution

The Nuxt advisory in the published inventory also groups a client-side script-scheme issue under its `open` option. That subfinding can execute script and should be analyzed as XSS/unsafe URL scheme handling. It is not an additional case record and should not be counted as a separate open redirect. [Nuxt advisory](https://github.com/nuxt/nuxt/security/advisories/GHSA-c9cv-mq2m-ppp3)

## Exclusions and deduplication notes

- Symfony CVE-2024-22243 and CVE-2024-22259 describe the same `UriComponentsBuilder` parser-differential issue with different inputs; they appear together in one published-case entry.
- WebOb CVE-2026-44889 is a bypass of the earlier CVE-2024-42353 fix. Both remain visible because the incomplete fix is valuable evidence, but they belong to one root-cause family.
- React Router CVE-2026-53669 is explicitly a follow-up to a prior navigation fix; it is retained as a regression example.
- Traccar and Nuxt each publish multiple sinks/subfindings within one advisory; each advisory counts once.
- Affected version ranges, deployment requirements, or exploitability that are missing from a source remain unknown; do not fill gaps from another product's behavior.
