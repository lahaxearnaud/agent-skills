# Open redirect corpus and skill update prompt

Use `research-backed-skill-builder` to maintain `corpus/security/open-redirect/` and `skills/security/open-redirect-static-review/`. Preserve existing records and direct citations. Research primary vendor/maintainer advisories, coordinated disclosures, standards, framework documentation, and high-quality issue reports for server-side HTTP redirects and client-side automatic navigation. Prioritize PHP/Symfony/Twig, JavaScript, Vue/Nuxt, authentication return paths, proxy/header inputs, and OAuth; include other web technologies when they add a distinct reusable code pattern.

For each case, record the direct source, date consulted, evidence/source type, affected versions, relevant route or feature conditions, actor and input, transformations/validation, exact automatic-navigation sink, source-attributed impact, remediation, unknowns, and related/bypass records. Read the source and available fix before promoting a result. Keep unreviewed issue reports and sparse CVE records in a separate leads file; separate open redirects from click-only external links, URL generation, SSRF, meta refresh, unsafe URL schemes, and XSS. Deduplicate records while retaining follow-up fixes when they teach a distinct parser or normalization failure. Do not meet a count by inventing cases or treating different identifiers as unrelated incidents. When a source is cited by the installable skill, add a concise attributed paraphrase to `skills/security/open-redirect-static-review/references/offline-sources.md`; preserve the URL for provenance but do not require browsing at review time. Update the offline note whenever its source's version, conditions, fix, or evidence status changes.

Derive static-review guidance from the evidence. The installed skill remains source-only: do not run the application, browser, payloads, scanners, or network requests. Add positive, negative, and incomplete-information evaluation scenarios; preserve outputs with and without the skill when separate agents are available. Make claims about severity, OAuth theft, CSP, versions, and browser/router behavior only when evidence supports them. Keep case-specific details and sources in references, and ensure the skill is portable after installation without this repository's corpus.

Write skill instructions and operational references in English by default; respond to the user in their requested language. Preserve source language and identifiers where needed. Verify Markdown links, frontmatter, case counts, internal references, `npx skills add . --list`, and a temporary installation if the CLI is available. Report limitations and observed evaluation results honestly. Review attribution and third-party rights, update the repository README/catalog and this maintenance guide, and create a targeted local commit; do not push or publish unless explicitly authorized.
